# Firewall 1 - NPC Pulse (OSINT recon)
Hack-A-PI - NPC Inc internal social feed - Flask - offline / closed-LAN

A deliberately information-leaking company social feed. Players perform OSINT
reconnaissance, recover real intel, and pivot into Firewall 2. This is pentesting,
not a flag hunt: the answer submitted to CTFd is the intel recovered (an ID, a
password, a codename, a host, a path, a code). No FLAG{...} strings anywhere.

Every stage's loot is the literal key to the next, so the chain is connected:
**staff ID -> login username -> password -> codename (folder name) -> the
still-live "deleted" post (found by hunting post ids) -> base64 portal path in
its SVG attachment -> F2's door.**

Browser-and-LLM solvable only. No local tools needed: the offline LLM decodes
base64, and SVG source is read in the browser.

> Organizer-only files (keep OFF the player network): `ORGANIZER_SOLUTION.md`
> (loot + full solve), `CHALLENGE_DOC.md` (pentest brief). The file to feed the
> event LLM is `LLM_HINTS.md` (hints only; delete the "Answer:" lines if you do
> not want the LLM to reveal final answers).

## Run

```bash
python3 -m venv venv && . venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

On start it prints the addresses to connect to, e.g.:

```
 * NPC Pulse - NPC Inc (Firewall 1)
 * Running on all addresses (0.0.0.0)
 * Running on http://127.0.0.1:5000
 * Running on http://192.168.0.191:5000
Press CTRL+C to quit
```

Players on the closed Wi-Fi open the `http://<LAN-IP>:<port>/` line.

- **Port:** defaults to **5000** so it does not clash with Firewall 2 (host :80).
  Change with `PORT`, e.g. `PORT=8080 python app.py`. Use :80 only if F2 is on a
  different host.
- **Server:** `python app.py` serves via **waitress** (production WSGI, handles
  the ~40-user load); it falls back to Flask's server only if waitress is missing.
  Debug is always off.
- **Health:** `curl -s http://localhost:5000/health` -> `ok`.

## Rotate the loot without code edits

```bash
cp .env.example .env     # edit LOOT_S1..S6
set -a && . ./.env && set +a && python app.py      # load env, then run
```

Unset/empty values fall back to the defaults in `config.py`. If you rotate S5
(the portal path is fixed to F2's real door, so normally leave it), update the F2
unlock answer in CTFd to match. If you rotate `LOOT_S2` (the password), keep the
clues consistent: the pet (Mochi) in the comments on post 127, the book (Dune) in
post 125, and the birth year ("turned 22") in post 123 - and keep the shape
letters+#+4digits - or it becomes unsolvable. (Windows PowerShell:
`$env:LOOT_S1="..."` before run.)

## Add your own photos / memes

Drop real social-media-style photos (food, scenery, memes, even a short GIF) into
`static/img/uploads/`, then point a post at them in `data/posts.json`, e.g.
`"image": "uploads/myphoto.jpg"`. They are pure decoration. The feed already ships
placeholder images you can swap (keep the filename, or change it and update the
post's `"image"`): food (#102), scenery (#105), gym (#112), the cat (#127) and
matcha (#126) that back the password clues, two noise images (#128/#129) and a
GIF (#130). A spare `uploads/meme-1.png` is included if you want to add a meme
post of your own. The **seven** Hack Day posters (`poster-1.svg`..`poster-7.svg`)
are generated by the app; the real one (default `poster-3.svg`, rotate with
`POSTER_REAL`) carries the Stage 6 code, the other six are decoys.

## Interactive chrome (believability, not part of the puzzle)

The feed is a working social app so it reads as a real internal tool:

- **Compose:** the Post box is live. Posts a player composes (text and/or an
  image) appear in **their own** feed only, are **never sent to the server**, and
  vanish on refresh. This is deliberate - it keeps the challenge state clean and
  stops one team polluting another's feed. (Ctrl/Cmd+Enter also posts.)
- **Notifications:** `/notifications` shows fictional, in-character activity.
  Pure flavour - it contains **no loot and no clues** (enforced by a test).
- **Login / logout:** `/login` and `/logout` are **standalone, centered pages**
  (their own layout, outside the feed chrome), the way real sites do it. The
  Messages link is hidden until you are signed in.
- **Like / retweet / follow:** client-side toggles, no state.

None of this affects the S1-S6 chain or CTFd answers.

## The 6 stages (one line, no spoilers)
| S | Surface | OSINT technique |
|---|---|---|
| Sign up | /signup | create intern INT-xxxx; the page states only the password SHAPE (two words + # + year) |
| S1 | feed + search | correlation / profiling -> her staff ID (login username) |
| S2 | staff login | the recipe (two favourites + # + birth year) is roasted out in #120 comments; pet via #127 comments, book #125, year #123 |
| S3 | her inbox (conversation list) | open the threads -> Theo's reveals the codename (folder name) |
| S4 | /projects/&lt;codename&gt;/removed-posts.log + post hunt | the note warns the attached .svg leaks info and unlisted posts still open by URL -> enumerate /post/&lt;id&gt; to find the still-live one (106) |
| S5 | /post/106 gated SVG attachment | base64 portal path in the SVG source (LLM decodes) -> **unlocks F2** |
| S6 | 7 posters, 1 real | hidden metadata token in one poster's SVG (bonus, hardest) |

Full solve + loot values: `ORGANIZER_SOLUTION.md`.

## CTFd setup
1. Create 6 challenges (S1-S6) with the loot from `ORGANIZER_SOLUTION.md`, matching case-insensitively.
2. Create the F2 challenge card (F2 URL + F2 answer).
3. Chain prerequisites: S1 -> S2 -> S3 -> S4 -> S5 -> **F2**. S6 independent (bonus).
4. Do NOT add the decoys (`NPC-0001`, `/employee-dashboard`, `NPC-1001`/`Welcome123!`, `sunshine2004`) as accepted answers.

## Design guarantees
- **Offline:** no CDNs, fonts, or network calls. Hand-written CSS, system fonts, SVGs generated locally.
- **No DB, no shell-out, no server-side state:** the login is a signed stateless cookie with a **server-only** key (never served to the client), so it cannot be forged and F2's cookie trick cannot skip the F1 login.
- **Only the intended things leak:** integer-only post routing (no traversal/LFI); `/resources/` and `/projects/` are fixed whitelists (unknown names -> 404); `/projects/skyline/` and the inbox require login; Jinja autoescaping on.
- **Fictional data only.**

## Tests
```bash
cd firewall1 && python -m pytest -q      # 37 passed
```
Covers each stage's loot at its intended point, the trolls and false loot, the
security negatives (traversal, unknown files, non-integer post IDs), the offline
guarantee, and loot rotation.
